# Primary-source findings: target replay numerics

Researched 2026-11-17. Scope: frozen Qwen3-8B target, reported Torch 2.13.0+cu126 / Transformers 5.15.0 / A5000, saved token 279 versus replay token 3070 for an allegedly identical prefix. This note establishes possible mechanisms and discriminating checks, not the cause of that observation. No repository files changed; no model downloads or inference jobs run. PyTorch's current `stable` pages redirect to 2.15, so the most relevant claims below were verified against the **v2.13.0 source tag**, not assumed from current defaults.

## What the sources establish

1. **Repeatability and shape invariance are different requirements.** PyTorch does not guarantee identical floating-point results for mathematically equivalent computations. Its v2.13.0 numerical-accuracy note explicitly distinguishes batched computations from individually computed elements, and operations on slices from slicing the result of a full operation. Its reproducibility note targets repeated calls with the same inputs on a specific platform/device/release. **Inference:** enabling deterministic algorithms cannot by itself establish equality between a one-token cached call and a full-sequence call, because those are different-shaped computations. [Numerical accuracy, v2.13.0](https://github.com/pytorch/pytorch/blob/v2.13.0/docs/source/notes/numerical_accuracy.md#L5-L38), [reproducibility, v2.13.0](https://github.com/pytorch/pytorch/blob/v2.13.0/docs/source/notes/randomness.md#L5-L14), [deterministic-algorithm scope](https://github.com/pytorch/pytorch/blob/v2.13.0/docs/source/notes/randomness.md#L94-L105).

2. **The exact Transformers version exposes a separate output-head shape difference.** Qwen3 uses a bias-free linear `lm_head`. Its forward default is `logits_to_keep=0`; hidden states are sliced immediately before the head, with no inference-time upcast. GenerationMixin defaults `logits_to_keep` to 1 for supported models. Thus an ordinary full-sequence forward and ordinary generation may project different numbers of rows even at the initial prefill. Assisted decoding overrides the count to candidate length plus one. The generation loop subsequently copies the already-computed final logits to FP32, applies logits processors, and uses argmax for greedy decoding. [Qwen3 head](https://github.com/huggingface/transformers/blob/v5.15.0/src/transformers/models/qwen3/modeling_qwen3.py#L431-L457), [projection](https://github.com/huggingface/transformers/blob/v5.15.0/src/transformers/models/qwen3/modeling_qwen3.py#L492-L495), [generation default](https://github.com/huggingface/transformers/blob/v5.15.0/src/transformers/generation/utils.py#L2612-L2616), [cast, processing, argmax](https://github.com/huggingface/transformers/blob/v5.15.0/src/transformers/generation/utils.py#L2892-L2925), [assisted override](https://github.com/huggingface/transformers/blob/v5.15.0/src/transformers/generation/utils.py#L3720-L3738).

3. **Changing rows can select a different GEMM implementation without random execution.** NVIDIA documents that cuBLASLt chooses kernels using problem sizes, GPU configuration, and other parameters. cuBLAS also documents deterministic summation of split-K partial results. Its run-to-run reproducibility guarantee has toolkit/hardware/stream restrictions; workspace configuration addresses concurrent-stream behavior. **Inference:** a deterministic split-K or differently tiled kernel can still round differently from another shape's kernel. These docs do not establish which kernel the user's head actually used. [cuBLAS 12.6 heuristics](https://docs.nvidia.com/cuda/archive/12.6.0/cublas/index.html#heuristics-cache), [GEMM numerical behavior](https://docs.nvidia.com/cuda/archive/12.6.2/cublas/index.html#gemm-algorithms-numerical-behavior), [reproducibility limits](https://docs.nvidia.com/cuda/archive/12.6.1/cublas/index.html#results-reproducibility).

4. **Attention backend is another independent numerical variable.** PyTorch v2.13 SDPA automatically selects implementations based on inputs and documents backend-dependent numerical differences. `sdpa_kernel` can restrict selection; the math backend keeps FP16/BF16 intermediates in FP32 and supports FP64. Qwen3 dispatches via its configured attention implementation and passes zero dropout in evaluation mode. Transformers' SDPA adapter computes `is_causal` partly from query length, so prefill and one-token decode need not take identical paths. This is intended behavior, not evidence of a masking defect. [SDPA documentation source](https://github.com/pytorch/pytorch/blob/v2.13.0/torch/nn/functional.py#L6426-L6445), [Qwen3 dispatch/dropout](https://github.com/huggingface/transformers/blob/v5.15.0/src/transformers/models/qwen3/modeling_qwen3.py#L259-L275), [SDPA query-length handling](https://github.com/huggingface/transformers/blob/v5.15.0/src/transformers/integrations/sdpa_attention.py#L104-L120).

5. **Precision settings need to be recorded, not inferred from tensor dtype alone.** PyTorch v2.13 documents optional TF32 for FP32 GEMMs and BF16 reduced-precision reductions enabled by default; it also describes the SDPA math backend's FP32 upcast/downcast behavior. Disabling reduced-precision reductions is a numerical intervention, not a promise of shape invariance. [TF32 and BF16 GEMM settings](https://github.com/pytorch/pytorch/blob/v2.13.0/docs/source/notes/numerical_accuracy.md#L108-L169). BF16 stores seven explicit fraction bits. **Derived example:** spacing is 0.125 for positive values in [16, 32), so distinct underlying logits can round to an exact tie. Converting those stored BF16 values to FP32 afterward preserves that tie. Recomputing a head with FP32 inputs/weights is a different experiment and cannot undo BF16 rounding already present in hidden states or stored weights. [NVIDIA BF16 representation](https://docs.nvidia.com/cuda/archive/12.4.0/cuda-math-api/struct____nv__bfloat16.html).

6. **Argmax and top-k have different tie semantics.** PyTorch argmax returns the first maximal index; top-k does not guarantee stable indices for tied elements. Therefore top-k display order cannot identify the greedy winner. If 279 and 3070 are exact tied maxima, and there is no smaller maximal token, argmax chooses 279. That is a conditional mathematical conclusion, not evidence that these particular logits were tied. Decimal display rounding also must not be mistaken for exact equality. [argmax, v2.13 source](https://github.com/pytorch/pytorch/blob/v2.13.0/torch/_torch_docs.py#L6840-L6845), [top-k, v2.13 source](https://github.com/pytorch/pytorch/blob/v2.13.0/torch/_torch_docs.py#L11557-L11562).

7. **There is a first-party maintainer investigation of cached versus full-sequence differences.** Transformers maintainer Joao Gante reported controlled CodeLlama/Llama and GPT-2 comparisons, identified changed matrix shapes as a mechanism, and observed layerwise divergence with much larger differences at 16-bit precision than FP32. The report includes a reproduction script. It is historical evidence for the mechanism, not a Qwen3-8B / 5.15.0 / A5000 reproduction or a proof that all discrepancies are numerical. Do not transfer its old Llama-specific FP16-versus-BF16 recommendation to Qwen. [Maintainer investigation, 2023-10-23](https://github.com/huggingface/transformers/issues/25420#issuecomment-1775317535).

8. **Explicit batch invariance exists as a distinct inference-engine feature.** vLLM documents batch invariance separately from deterministic scheduling, including dedicated kernel choices and consistent reduction behavior. Qwen3-8B is among its tested models. This demonstrates that batch invariance requires additional implementation work; it does not establish that stock Transformers has it or that switching engines would reproduce an existing Transformers token stream. [Batch invariance](https://docs.vllm.ai/en/stable/features/batch_invariance/), [reproducibility scope](https://docs.vllm.ai/en/stable/usage/reproducibility/).

## Useful reports, with limitations

- [Transformers #36536](https://github.com/huggingface/transformers/issues/36536) provides a Llama-3.1 BF16 cached/uncached reproduction on older Transformers 4.49 / Torch 2.6. A [participant's follow-up](https://github.com/huggingface/transformers/issues/36536#issuecomment-2702230493) reports improved FP32 agreement, but printed agreement is not a universal bitwise guarantee.
- [Qwen repository #1357](https://github.com/QwenLM/Qwen3/issues/1357) reports shared-prefix hidden-state differences when suffixes change. Despite the repository name, the model is **Qwen2.5-7B**, and there is no substantive maintainer diagnosis. It supports only that such a report exists.
- [Transformers #46190](https://github.com/huggingface/transformers/issues/46190) concerns **Qwen3.5 GatedDeltaNet on CPU**, a different architecture. Its reported cache/full-sequence discrepancy cannot diagnose dense Qwen3-8B. Likewise, Qwen3-VL hidden-state API bugs do not establish a dense Qwen3 bug.

## Diagnostic interpretation (proposed; not executed)

- First distinguish identical-call repeatability from disagreement across paths. Repeat each path unchanged before attributing a mismatch to nondeterminism. A repeatable disagreement points to an input/configuration difference, implementation defect, or shape/backend/precision effect; it does not distinguish those by itself.
- At the same exact token prefix and prediction position, compare the two competing logits, exact max-equality set, greedy argmax, and processed generation scores. Record model revision, dtype, masks/positions, cache contents and history, backend, head row count, and precision flags. A saved token alone cannot recover its original margin or tie status.
- Isolate the head with one captured hidden-state tensor: project the last row alone versus the full matrix then slice. This holds transformer/cache numerics fixed. Compare BF16 projection, FP32 projection with TF32 disabled, and BF16 logits merely converted to FP32 as separate interventions.
- Independently compare full-sequence versus cached processing while holding head row count and SDPA backend fixed. A one-token decode after a freshly recomputed prefix cache is not necessarily the same cache history as a long sequential generation; preserve that distinction.
- For logits vectors differing by at most epsilon in each coordinate, a reference top-two margin greater than 2*epsilon is sufficient for stable argmax (triangle-inequality derivation). Small margin permits a flip but does not prove numerical noise caused it. Exact matching remains a valid requirement if the verification procedure is meant to reproduce the generator's numerical behavior.

## Follow-up: independently verified batch-invariant implementations

- Thinking Machines' original engineering report explicitly distinguishes run-to-run determinism from batch invariance. It identifies RMSNorm, matmul, and attention reductions as separate concerns; attention must also be invariant to chunked prefill and cache boundaries. It explains why fixing the number of KV splits is insufficient and instead describes a fixed split size. Its authors state that their fixed-split attention changes were not included in the original code release. These are implementation findings, not evidence that a particular PyTorch SDPA backend is the remaining culprit here. [Original report, sections on invariance and attention](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/).
- I inspected `batch_invariant_ops` at current commit **f22b1fbe534b1fe045080f44a970a441caaf3c4f** (2025-11-04). Its mode registers replacements for `aten::mm`, `aten::addmm`, `aten::_log_softmax`, and `aten::mean.dim`; it does **not** replace SDPA or `bmm` there. Its attention helper only returns tile sizes. The vLLM example explicitly requires an additional vLLM PR. Thus simply wrapping a stock Transformers forward with this context manager is not a documented end-to-end cache/chunk invariance guarantee. [Exact registrations](https://github.com/thinking-machines-lab/batch_invariant_ops/blob/f22b1fbe534b1fe045080f44a970a441caaf3c4f/batch_invariant_ops/batch_invariant_ops.py#L500-L510), [attention helper](https://github.com/thinking-machines-lab/batch_invariant_ops/blob/f22b1fbe534b1fe045080f44a970a441caaf3c4f/batch_invariant_ops/batch_invariant_ops.py#L535-L539), [vLLM example prerequisite](https://github.com/thinking-machines-lab/batch_invariant_ops/blob/f22b1fbe534b1fe045080f44a970a441caaf3c4f/deterministic_vllm_inference.py#L1-L3).
- Additional web searches and GitHub issue API searches did not locate a well-matched dense Qwen3-8B cached/uncached numeric-mismatch reproduction. This is a search limitation, not evidence none exists. [Transformers #41944](https://github.com/huggingface/transformers/issues/41944#issuecomment-3480971879) has a maintainer explanation of numerical differences across attention implementations for an Intern-S1-mini/Qwen3-8B variant, but it concerns training outcomes, not the current frozen-target replay. [Qwen3-0.6B cache issue #38727](https://github.com/huggingface/transformers/issues/38727#issuecomment-2961618731) was diagnosed as chat-template removal of thinking text, so its cached prefix differed from the newly tokenized request. It is not analogous once token-prefix identity is established.
